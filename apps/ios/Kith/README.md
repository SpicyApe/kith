# Kith iOS app target

Written on Windows without an Xcode toolchain, so treat the first Mac build as the
real compiler. This file lists what is here, the deviations from `apps/ios/PLAN.md`,
and the handful of API calls most likely to need a one-line fix.

## Before you build

1. `cp Config/Config.example.plist Config/Config.plist` and fill in `SUPABASE_URL`,
   `SUPABASE_ANON_KEY`, `WEB_BASE`. `Config.plist` is gitignored.
2. `cd apps/ios && xcodegen generate && open Kith.xcodeproj`.
3. `Info.plist` and `Kith.entitlements` are generated by XcodeGen from `project.yml` —
   do not add them to the repo.
4. `KithCore` and `LineupEngine` are fully implemented and tested (`swift test` in
   `packages/KithCore` and `packages/LineupEngine`); no unimplemented contract stubs
   remain in either package or in this target.
5. Without `Config.plist` the app no longer traps: `AppConfig` logs the missing key and
   `RootView` shows a "Config.plist missing" banner, so a first run is diagnosable.

## Deviations from PLAN.md (and why)

- **`Model/Session.swift` declares `AuthSession`, not `Session`.** `import Supabase`
  already exports a `Session` struct; shadowing it makes `client.auth.session` painful
  to read. The `AppModel` property is still called `auth`.
- **`Views/Shared/Theme.swift` is a new file** (colours, card, two button styles). It is
  under `Views/Shared/*.swift`, which PLAN.md globs.
- **`HeatmapView` and `StatsGrid` live inside `ProfileView.swift`**, as PLAN.md's table
  implies (one row for the whole Profile screen).
- **The onboarding tail is modelled in `AppModel`, not `OnboardingFlow`.**
  `KithCore.OnboardingStep` is a frozen contract with no `friendsFound` or
  `notificationsPrompt` case, so `AppModel.tail` (`.none` / `.friendsFound` /
  `.notifications`) drives those two screens as a `fullScreenCover` from `RootView`.
- **Resuming at the name step replays events.** `OnboardingFlow.step` is `private(set)`,
  so `AppModel.flowAtName()` applies `.phoneEntered("")` then `.codeVerified` to reach
  `.name` for a signed-in user with no `users` row.
- **The reveal strip falls back to labels only when `reveal` is empty.** `KithAPI` now
  has `reveal(itemIds:)` (gated `list_items` select) and `AppModel.reveal` is loaded
  best-effort after a submit or when today is already played, so the strip normally
  renders "label · value · fact". Offline, the call fails silently and the strip shows
  the correct order without values — deliberately, rather than showing nothing.
- **The one-time contacts re-ask is a separate `AppModel` flag, not an `OnboardingFlow`
  step.** `KithCore.OnboardingFlow` can only reach `.contactsPrompt` from `.name`, and
  replaying events to get back there would also drop the user into `.playing`, which
  would re-trigger the post-play onboarding tail. `AppModel.showContactsReask` (persisted
  via `StoreKey.contactsReasked`) makes `RootView` show `ContactsPromptStep` bare instead.
- **`StoreKey.contactsReasked` stores a `Timestamp`, not a `Bool`.** `FileStore` round-trips
  top-level JSON fragments poorly (the same reason `Timestamp` exists at all), so the flag
  is "when we re-asked" and its presence is the boolean.
- **No "me" contact card prefill on the name step.**
  `CNContactStore.unifiedMeContactWithKeys(toFetch:)` is macOS-only; iOS has no
  equivalent. The field starts empty.
- **`CNContactFetchRequest` fetches a fourth key.** Alongside given/family/phone it adds
  `CNContactFormatter.descriptorForRequiredKeys(for: .fullName)`, because
  `CNContactFormatter` raises an exception if the contact was fetched without it.
- **`CNAuthorizationStatus.limited` is matched by raw value (`4`), not by name**, so the
  file still compiles against the iOS 17 SDK if CI's Xcode is 15.x.
- **Your own board row is pinned at the bottom only when the list has more than 8 rows.**
  A real "sticky if scrolled out of view" needs scroll-offset tracking; this is the
  cheap approximation.

## Where I'd look first if it doesn't compile

Honest list, roughly in order of risk.

1. **supabase-swift 2.x call shapes** (`Model/Session.swift`). I used
   `SupabaseClient(supabaseURL:supabaseKey:)`, `auth.signInWithOTP(phone:)`,
   `auth.verifyOTP(phone:token:type: .sms)` → `AuthResponse` with `.user.id: UUID`,
   `auth.session` (async throws) → `.accessToken`, `auth.signOut()`. I deliberately did
   **not** use `auth.currentUser`; `userId()` reads `session.user.id` instead. If
   `verifyOTP` returns something else in the pinned version, only
   `AuthSession.verify(phone:code:)` needs changing.
2. **`@MainActor` on `struct KithApp: App`.** Added so `@State private var model =
   AppModel()` can call a main-actor-isolated initializer under
   `SWIFT_STRICT_CONCURRENCY=complete`. If Xcode objects to `@main` plus `@MainActor`,
   drop the attribute and make `AppModel.init` `nonisolated` instead.
3. **`@MainActor` closures passed to `.task`** (`TodayView.loadIfNeeded`,
   `BoardView.completeFriendsFoundStep`). `.task` takes a `@Sendable` closure that does
   not inherit the view's isolation, so each one awaits a main-actor method rather than
   touching `model` inline. If the SDK's `task(priority:_:)` turns out to be
   `@MainActor`-isolated, these can be inlined again.
4. **`URLSession.shared` in a `Sendable` struct.** Fine in the Xcode 15/16 Foundation
   overlay; if it warns, wrap the call in a `nonisolated(unsafe)` static session.
5. **`ForEach(Array(engine.currentOrder.enumerated()), id: \.element)` with `.onMove`.**
   The reorder maths (`AppModel.moveRows`) converts SwiftUI's "insert before" index to
   the engine's from/to. Worth exercising by hand on device; locked rows carry
   `.moveDisabled(true)` so the engine should never see a locked index.
6. **`TileList` has a fixed `@ScaledMetric` height (330 pt)** because a `List` inside a
   `ScrollView` needs one. If the five rows clip at the largest accessibility sizes,
   raise it or move Today off the `ScrollView`.
7. **`SwiftUI.Circle()` is qualified** in files that also `import KithCore`, because
   `KithCore.Circle` collides with the SwiftUI shape. `CirclesView` spells the model
   type `KithCore.Circle` for the same reason. If you add a new view file that uses
   both, remember the qualification.
8. **`AppIcon.appiconset/Contents.json` has no `filename`.** `project.yml` now names
   `ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon` (and `..._GLOBAL_ACCENT_COLOR_NAME:
   AccentColor`), so Xcode will warn about the missing image; CI builds with
   `CODE_SIGNING_ALLOWED=NO` so it should not fail, but drop a 1024×1024 PNG in and add
   `"filename"` before any TestFlight upload.
9. **`Kith/Config/Config.plist` is declared twice in `project.yml`** — once implicitly by
   the `Kith` directory scan and once explicitly (`buildPhase: resources`, `optional: true`)
   so a missing, gitignored plist does not break `xcodegen generate`. XcodeGen dedupes by
   path; if a future version double-adds it, delete the explicit entry, not the scan.
10. **The reveal strip's `RevealLine` sits at file scope in `ResultsView.swift`**, not
   nested in the view, so it does not inherit `@MainActor` and can satisfy
   `Identifiable`'s nonisolated `id` requirement.
